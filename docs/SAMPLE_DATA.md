# Sample Data and Demo Scenario

## Goal
20–30 legally safe, clearly SYNTHETIC invoice PDFs (label them synthetic in README/UI/reports) with KNOWN ground truth, generated by a deterministic script
(fixed seed) so expected outputs cost no manual labeling. Do not use confidential customer documents.
Libraries: `reportlab` or `fpdf2` + `Faker` (verify availability/licenses). Output: `sample_data/pdfs/*.pdf`
and `sample_data/ground_truth.json`. PDFs must have a text layer.

## Variation axes
- Layouts (5): A classic single column; B logo header + two-column address block; C table-heavy;
  D compact purchase-order style; E multi-page with totals on page 2.
- Date formats: ISO, `15 Jan 2026`, `January 15, 2026`, `15/01/2026` (ambiguity case).
- Currencies: USD, EUR, GBP, INR (symbol vs code).
- Amount formats: with/without thousands separators; tax rounding cases (e.g. 3-decimal tax rounded to 2).
- Optional fields: tax absent (tax-free invoices). PO number may appear on documents ONLY as a distractor; it is not an extracted field.
- Vendor names with suffix/punctuation variants (Ltd., LLC, Inc.).

## Deliberate difficulty (tagged `hard`)
- Multiple totals: subtotal, "Total before tax", "Amount due", "Balance carried forward" (total_amount trap).
- Lookalike identifiers: invoice number vs reference/PO/order number.
- Totals on a later page. Noisy text order after extraction.
Aim: ~20 normal, ~5 hard. Tags drive reporting, not scoring.

## ground_truth.json (shape)
```json
{"cases":[{"name":"inv-001","file":"pdfs/inv-001.pdf","layout":"A","tags":["simple"],
 "expected":{"invoice_number":"INV-1042","vendor_name":"Northstar Supplies","invoice_date":"2026-01-15",
 "currency":"USD","subtotal":"1000.00","tax_amount":"180.00","total_amount":"1180.00"}}]}
```
An import script loads PDFs + expected outputs through the public API (not by writing to the DB directly).

## Demo scenario (must be reproducible)
Requirement from PROJECT_UPDATE.md: the regression must not depend on an LLM randomly failing.

**Mechanism: `replay` provider.** A provider adapter implementation that, instead of calling an LLM, returns recorded raw
model outputs from a fixture file keyed by document sha256:
`sample_data/recordings/<name>.json` = `{"meta": {...}, "outputs": {"<sha256>": <raw model output in extraction-contract format>}}`.
Everything downstream (parsing, normalization, evaluation, comparison, policy, report) runs for real on those outputs.
Workflow version config: `{"provider":"replay","model_identifier":"replay-v1","config":{"recording":"sample_data/recordings/v1.json"}}`.

- **v1 (baseline):** recording where all critical fields are correct on the dataset, except a small number of existing failures
  (so UNCHANGED_FAIL exists). Real extraction logic is not required to produce it.
- **v2 (broken candidate):** recording with vendor_name improved on some cases BUT incorrect `total_amount` on several cases
  (e.g. returns "amount due" / balance-forward figure). Expect REGRESSION (critical) → policy FAIL.
- **v3 (improvement):** fixes a v1 failure (e.g. a date format) with no new critical regression → PASS (or REVIEW_REQUIRED if a high-severity change).

Honesty rules:
- Recordings may be produced by (a) recording a real live-provider run, or (b) hand/script authoring. If any outputs are
  edited or injected to create the regression, set `meta.injected_fault=true` with a description, and say so in the README.
- The comparison engine must never contain demo-specific logic; it evaluates actual run data.
- Automated tests use the same replay/mock mechanism. An optional live-provider run is manual and its measured results
  (if any) are reported as measured, never assumed.
- Replay is a deterministic test fixture, not evidence of LLM accuracy. Do not present replay results as model performance.
